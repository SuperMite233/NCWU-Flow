# 华水信息流扩展功能设计

**日期：** 2026-08-30  
**状态：** 已获用户批准，待规范评审

## 目标

在现有华北水利水电大学学生信息流 Android App 的基础上，扩展第二课堂和竞赛信息能力，同时保持官方登录态复用、不保存账号密码，并让活动状态、竞赛时效和个人数据在 App 内有一致的展示与交互。

## 已确认的产品范围

第二课堂顶部二级导航包含：

- 活动报名
- 活动验证
- 成绩单
- 已报活动

竞赛顶部二级导航包含：

- 竞赛报名
- 竞赛消息

底部导航仍为第二课堂、竞赛列表、设置。活动列表必须同时保留报名中、待验证和即将开始报名的活动，通过状态标签区分。竞赛列表默认隐藏结束时间早于当天七天以上的竞赛。已报活动首屏及每次分页最多显示十条。

活动验证首版采用兼容优先策略：在 App 内嵌学校官方验证页面，复用当前 WebView 登录 Cookie，由官方页面完成微信二维码或验证码流程。App 不保存学号、密码、二维码 token，也不复制微信登录协议。

## 设计原则

1. **官方页面优先。** 新接口先通过已登录浏览器确认真实请求、参数和响应格式，再加入解析器；不根据猜测硬编码学校接口。
2. **会话只存 Cookie。** 现有 WebView 登录产生的 Cookie 继续作为 OkHttp 请求凭证，清除登录状态时同时清理 WebView 和 CookieManager 状态。
3. **解析与业务规则分离。** HTML/JSON 解析器只负责转换数据；活动状态归一化、竞赛时间过滤、成绩目标进度和分页规则使用纯 Kotlin 函数实现，以便单元测试。
4. **未知数据保守保留。** 日期缺失、状态未知或字段格式变化时，不因为无法解析而静默丢弃用户可能需要的信息。
5. **Material 3 一致性。** 沿用现有主题、深色模式和 Material 3 组件；状态同时使用文字和视觉样式表达，不只依赖颜色。

## 架构

### 数据层

`CampusRepository` 负责网络请求、Cookie 复用、响应 Cookie 同步以及认证失效判定。它不保存账号密码，不暴露 OkHttp 响应给 UI。

`CampusParser` 负责将学校 JSON、HTML 或脚本中的数据转换为模型。每一种新增数据格式都应有独立解析函数和固定样例测试。

新增或调整的模型边界如下：

- `ActivityItem` 增加可测试的状态表示，原始状态文本仍可保留用于详情展示。
- `CompetitionItem` 保留原始状态和日期文本，过滤逻辑接收显式的当前日期或 `Clock`。
- 新增个人已报活动分页模型，至少包含当前页、页大小、是否还有下一页和项目列表。
- 新增成绩单模型，包含课程或成绩项目、成绩值、学分或权重（若官方数据提供）以及学期标识。
- 新增竞赛消息和活动消息模型，包含标题、正文摘要、发布时间和官方详情链接（若官方数据提供）。

分页模型必须支持服务端总数缺失的情况：优先使用服务端的总数或下一页标识；只有在响应没有分页元数据时，才以返回数量小于十条判断结束。

### 业务层

`MainViewModel` 继续作为 Compose 页面状态入口，但将各二级页面状态分开保存，避免切换菜单时重复清空已经加载的数据。

ViewModel 负责：

- 触发各数据源刷新和加载更多。
- 将 `LoadResult` 转换为页面可表达的加载、认证、错误和空状态。
- 保存已报活动当前页、加载更多状态和是否还有下一页。
- 保存最新学期目标设置，并计算成绩目标进度。
- 对认证失效统一提示用户重新登录，不把凭证写入 DataStore。

纯业务函数建议采用以下语义：

```kotlin
fun normalizeActivityStatus(raw: String, signupStart: LocalDateTime?, now: LocalDateTime): ActivityStatus

fun shouldShowCompetition(item: CompetitionItem, today: LocalDate): Boolean

fun calculateTermProgress(scores: List<GradeItem>, target: Double): TermProgress
```

活动状态归一化规则按优先级处理：

1. 服务端明确表示待验证，归一化为 `PENDING_VERIFICATION`。
2. 服务端明确表示即将开始报名，归一化为 `UPCOMING_SIGNUP`。
3. 服务端明确表示报名中，归一化为 `SIGNUP_OPEN`。
4. 服务端明确表示已结束，归一化为 `ENDED`。
5. 如果原始状态未知，归一化为 `UNKNOWN`，并保留项目。

如果服务端只提供时间而没有可靠状态文本，则使用时间推导状态；时间不完整时优先使用服务端文本，无法判断时使用 `UNKNOWN`。

竞赛过滤规则为：

- 结束日期为空或解析失败：保留。
- 结束日期大于等于 `today.minusDays(7)`：保留。
- 结束日期早于 `today.minusDays(7)`：默认隐藏。
- 过滤只影响默认列表，不删除仓库中的原始数据；详情或后续筛选可以复用完整数据。

### UI 层

在现有 `ActivityScreen` 和 `CompetitionScreen` 内增加顶部二级菜单，使用 Material 3 `SingleChoiceSegmentedButtonRow` 或现有项目兼容的等价组件。二级菜单固定在列表内容顶部，切换时保留当前底部导航目的地。

第二课堂页面：

- “活动报名”显示状态归一化后的活动列表，待验证和即将开始报名项目与报名中项目同列表展示。
- “活动验证”打开官方验证页面的内嵌 `SchoolWebPage`，页面关闭后返回二级菜单，不清空活动列表。
- “成绩单”显示当前学期成绩项目、目标值和进度；目标未设置时显示设置入口或明确的未设置状态。
- “已报活动”显示分页列表；底部使用明确的“加载更多”操作和加载状态，避免自动连续请求。

竞赛页面：

- “竞赛报名”使用现有竞赛列表、默认七天过滤和排序控件。
- “竞赛消息”显示解析后的消息列表，详情优先打开官方页面或使用已解析正文。

所有页面需要覆盖：首次加载、下拉或按钮刷新、空结果、认证失效、网络错误、加载更多失败和重复点击保护。交互控件满足至少 44dp 触控尺寸，图标按钮提供内容描述。

### 活动验证页面

首版不实现原生微信登录协议。`SchoolWebPage` 需要：

- 只允许学校相关域名导航，保持现有明文 HTTP 升级策略。
- 复用 WebView Cookie，并将必要的登录状态同步给后续请求。
- 支持官方页面所需的相机或文件权限请求，但权限结果必须反馈到页面。
- 关闭或返回时释放 WebView 资源，不主动删除登录 Cookie。
- 页面加载失败、登录失效和验证完成时提供可理解的状态提示。

在实现前，用 `agent-browser` 在已登录会话中确认活动验证入口、二维码/验证码承载页面和完成回调。确认结果只用于代码中的接口和页面选择，不保存账号密码或个人 token。

## 数据流

1. 用户在 WebView 中完成官方统一认证。
2. WebView 的 CookieManager 保存会话 Cookie。
3. ViewModel 请求 Repository 加载活动、竞赛或个人数据。
4. Repository 使用对应官方 URL、Referer、User-Agent 和 Cookie 发起请求，并同步响应 Cookie。
5. Parser 转换响应为模型。
6. 业务函数完成状态归一化、竞赛默认过滤、分页和成绩目标进度计算。
7. Compose 根据独立页面状态渲染列表、详情、错误和认证入口。

## 错误处理

- 登录页面或认证跳转被响应时，返回 `LoadResult.AuthenticationRequired`。
- HTTP 非成功、解析异常或网络超时返回带用户可读信息的 `LoadResult.Error`。
- 解析单条数据失败时跳过该条并继续处理其他项目；整个响应结构失效时返回错误，而不是伪造空列表。
- 分页加载失败不覆盖已经显示的前页数据，保留重试按钮。
- 成绩目标小于等于零时不计算百分比，显示目标配置错误并阻止保存。
- 成绩进度限制在 0% 至 100%，并同时显示原始分数和目标值，避免只用进度条传达信息。

## 设置与隐私

最新学期目标使用 DataStore 保存，键名与现有显示设置分开。只保存目标数值和学期标识，不保存课程成绩之外的认证凭据。

清除校园网站登录状态时：

- 清理 WebView Cookie。
- 清理 CookieManager Cookie。
- 清空需要认证的页面状态。
- 保留主题、后台扫描和学期目标设置。

后台扫描仅扫描用户选择的类别；新增消息源接入后再映射到现有扫描类别，不改变用户已经保存的扫描开关默认值。

## 测试

### 单元测试

先写失败测试，再实现对应代码：

- 活动状态文本和时间归一化，覆盖待验证、即将开始报名、报名中、已结束和未知状态。
- 活动列表保留待验证、即将开始报名和报名中的项目。
- 竞赛七天过滤，覆盖恰好七天、超过七天、日期缺失和日期格式错误。
- 活动消息、竞赛消息、成绩单和已报活动分页响应解析。
- 已报活动页大小为十条、页码递增、最后一页结束判断和分页失败状态。
- 成绩目标进度计算，覆盖未设置目标、目标为零或负数、未达标、达标和超过目标。
- 保留现有活动报名和竞赛时间线解析测试。

## 非目标

- 不保存或提交用户学号和密码。
- 不在首版复制微信登录协议或实现独立微信账号认证。
- 不全局放开明文 HTTP。
- 不重写现有底部导航、后台扫描架构或主题系统。
- 不在没有官方接口证据时猜测或伪造学校数据。
